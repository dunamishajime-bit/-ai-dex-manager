# 新モデルの勝率60%研究（2026-10-08）

全24案×往復10/20/30bps=72ケース。全体勝率60%以上の比較候補を得たが、全ロジックが60%以上かつ黒字になる条件は未達。LIVEは変更していない。

## 基準と改善候補

基準は前回Q_RET14_DELTA（現行候補へ競合しないQ102 REV追加候補を加えた研究構成）。初期1万円、追加入金なし、2025-08-10～2026-08-10 UTC、USD決済、as-of ECB FX換算、Funding・所有権・Gross・優先順位・日次制限・Cooldown込み。基準を3コストで再実行し、指標と台帳のbyte一致を確認。V12 Exitの再実装は1978/1978件の基準Exit一致を確認。

重点候補 `TP05_STOP075_REL6_G050`：V12だけに以下を適用する。

- Entry直前の確定H1 closeから算出する6h BTC比相対騰落を方向調整し、0以上を要求（LONGは相対強い、SHORTは相対弱い）。REL6_POSというCase名は厳密な正ではなく非負の意味。
- Take ProfitをEntry ATRの0.5倍。
- 初期StopをEntry ATRの0.75倍、従来の価格0.5%下限は保持。
- 要求Grossを元のリスクSizingの0.50倍にする。全注文を固定0.50xにするものではない。取引所lot/min/max判定を引き続き適用。
- ATR1.0到達後trail1.0ATRという設定も保持するが、TP0.5ATRが先に到達すればTP決済するため、主要な挙動は短いTPと初期Stopで決まる。

重要：重点候補のV12は勝率60.74%でもPF0.932、unit平均損益も負。これはV12のエッジ回復を証明していない。高勝率化と、負の寄与をSizingで抑えて他のSleeveの利益を残す効果を分ける。V12を本番改善済みとは扱わない。

Q102は基準63.91%。MR35件は48.57%だが、MR除外BTは全体最終資産431.9→291.6万円、勝率48.04→47.38%へ悪化した。弱い群の除外でも資金・Cooldown・所有権経路が変わり、全体が良くなるとは限らない。今回の重点候補ではMRを維持。

PENGUは基準75.38%で既に60%以上。SHORT_V20も21件76.19%だが実現USD損益は負であり、勝率だけでは選別しない。FET/V52/HYPEの本体は変更せず、全体で資金経路が変わる影響だけを再計算した。FET7件など小標本は確証不足。

Idle SHORT基準は64.62%だがDOT20件50%、RENDER17件52.94%に弱さがある。重点候補ではIdle58.33%、Residual54.29%となり、全Sleeve60%は未達。単に全体の勝率63%を「全部改善」と呼ばない。これらの小標本ルートには追加Forward evidenceが必要。

V12を全除外する診断では勝率67.50%、最終1605.7万円、DD19.69%だが、取引1534→440、Entry日328→265へ減少。高勝率群だけに変える比較として示し、V12を保持した改善案と区別する。本番停止を推奨する結論ではない。

前後半は未使用holdoutではなく、同じ既使用期間の時間分割。30bps前半は60%未満。週cluster bootstrap（54週、2000回、seed固定）でも30bps下限は60%未満。Wilsonは独立Bernoulliを仮定した記述用で、週bootstrapも24案選択の多重比較調整をしていない。将来勝率60%を確証できない。

最初の13案でExit/Entry/除外を比較し、その結果からStop9案、さらにSizing2案を追加。全24案は探索的in-sample研究であり、最良値の採用による過学習リスクがある。勝率60%目標は全体の手数料・Funding込み決済済みポジション単位。部分決済の回数で勝率を水増ししない。

## 再現・検証・限界

`python scripts/research/test_wr60_adapter.py` → `python scripts/research/run_wr60_new_model.py` → `python scripts/research/build_wr60_diagnostics.py` → `python scripts/research/postprocess_wr60_new_model.py` → `python scripts/research/verify_wr60_new_model.py` の順に実行。市場Klinesは `DISDEX_MARKET_KLINES`、エンジン用市場/Funding/FXは前回support wrapperのデータ設定を用いる。前回gate-fixes成果物とbaseline入力が必要。市場入力のhash/provenanceは前回market-input-manifest.jsonを参照。

V12実装定数stop2.477ATR・TP3.1995ATR・trail0.20ATRを基準として保持した。Gap Stopは不利な始値、H1内StopとTPが同時接触ならStop優先、完成2H極値を見たStop更新で価格が通過済みなら次H1始値をquote代理として使用。9adapterテスト、全72台帳の独立勝率/PF/損益/入金/cashflow/所有権検証、基準3コストの台帳byte一致を確認。DDはengine算出値で独立tick再計算していない。

Entry相対6hは確定足だけを使用。MFE/MAE/Givebackファイルは事後記述用H1上限でEntryには使用しない。V52の対応Aster足は未収録なのでMFEはnull。partial exitのGivebackは最終残数量のprice returnとして限定する。

凍結したPENGU/FET/Q102/V52候補、既存Q delta、現時点filters、H1価格proxyに依存し、過去tick/L2/pending/nonasync freshness/実marginを完全再現しない。現行VPSから全候補を再生成した正式BTではない。結果をLIVE収益予測として扱わない。

成果物・研究スクリプトだけ保存し、Productionパラメータ、LIVEコード、Runner、注文には変更なし。現時点の結論は「全体60%以上の比較候補あり」「全Sleeve60%・V12黒字化・未使用期間での再現は未達」。次は重点候補をForward Shadowで評価し、V12のPF回復とIdle/Residualの低勝率ルートを検証する。
