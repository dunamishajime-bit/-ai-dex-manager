# 全Gate修正・比較BT（2026-10-08）

実装修正は数量丸めによる不必要な見送りと、整数数量の送信文字列の破損です。BTC Gateを全体で緩める根拠は得られませんでした。変更は研究ブランチに保存し、LIVEのコード・閾値は未変更です。

## 実装修正

- Idle SHORT / Residual LONG: full 1.0xの空き枠は従来どおり必要。1.0x目標を取引所lot stepへ切り下げた結果だけ許可し、実notional/grossを予約する。余分なlot削減、増量、off-grid、min/max違反、数値/送信文字列の不一致は拒否する。
- 共通Normalizer: precision=0の「300→3」「121000→121」を修正。小数部のゼロだけ除去する。これは全ロジックの発注・決済数量へ影響し得る不具合であり、過去の実約定への影響範囲は別途注文台帳で調べる必要がある。
- 実Normalizer280ケースでは旧Idle厳密1.0x判定の許可9件→修正後280件。修正前は16件の送信文字列不一致を確認。これは境界値検証セットで、実際の機会増加率を示すものではない。
- Linuxの関連99テスト、型チェック、独立コードレビューに合格。

## 比較条件と重要なモデル修正

期間2025-08-10～2026-08-10 UTC、初期1万円、追加入金なし、複利、USD決済・as-of ECB USDJPY換算。往復コスト10/20/30bps、Funding、所有権、優先順位、gross上限、Cooldown、日次損失制限を含むH1参照ポートフォリオモデル。全16案×3コスト=48ケース。PFはUSD決済損益、最終資産はJPY、DDはエンジン報告のMTM。

V12旧Exitモデルは、2H足の完成後に引き上げたStopをすでに通過していても、そのStop価格で約定させていた。LIVE実装はfresh quoteで撤退するため、新モデルは次H1始値をquote代理値として採用。基準候補1978件のEntryキー・要求grossは一致し、1568件のExitが異なる。旧Exit参照と修正Exitの資産差はGate改善によるものではない。このH1代理モデルにもtickの誤差があり、過去正式BT全体の否定・実LIVE損益の推定ではない。

HYPEは実runnerに合わせてtrailingDistanceを固定TPへ変換。候補を先に単体position/cooldownで間引かず、全候補のExitを作り、ポートフォリオで採否・実採用後のCooldownを判定した。過去のGate監査ファイルは維持した。

CURRENT_H1_STRICTは修正Exit+旧数量判定、LOT_FLOOR_FIXは修正Exit+新数量判定。双方とも正しい数値数量で発注できた想定で、過去の壊れた送信文字列は再現しない。LEGACY_EXIT_REFERENCEは旧V12 Exitを使う原因切り分け専用の参照値。

## 判断

数量修正は10bpsで取引1442→1528、EntryがあったJST日数311→326、最終資産185.0→359.6万円。ただしDD23.53→25.47%へ悪化し、機会増加とDD削減の両立は未達。20/30bpsでも資産は改善する。

V12 BTC閾値2.0→1.5/1.0%は取引機会を増やすが、収益・高コスト耐性は安定して改善しない。一律緩和を採用しない。Score85や出来高55%も一部利益が増える一方、高コストでは優位性またはDDが崩れる。

Q_RET14_DELTAはREVの符号調整14日リターン下限10→7.5%の追加候補。数量修正比で10bps最終資産+20.1%、DD25.47→23.82%、取引+6、Entry日+2。20/30bpsでも利益・DDは改善。ただしHIGH_VOLを固定した既存候補へ同時刻競合のないS34差分だけ追加した検証であり、全selectorの再判定ではない。追加6件と少なく、再利用済みデータで選択したため本番閾値変更を裏付けるには不足。次のForward Shadow候補とする。

HYPE slope50は収益が改善したがEntry日数は増えず、10bps DDは微悪化。Idle/Residual相対強弱緩和は収益悪化。PENGU/FET/V52の本体条件・M05 Shadow・Q102 HIGH_VOL SHORT 0.60xは変更していない。昨日の無発火原因は既存[全Gate監査](../all-gates-opportunity-20261008/README.md)を参照し、BTC以外の基本Setup/鮮度/丸めも区別する。

## 限界・再現

前後半は時間分割の頑健性確認であり、未使用holdoutではない。Entryが分割境界より前・Exitが境界以降のトレードは半期集計だけ除外し、年間集計に含む。Entry日数はdistinct JST datesであり、UTC365日期間はJST366日へ跨ぐため「365-Entry日数」は厳密な無発火日数ではない。

H1価格・次H1 quote代理、現在観測filters、凍結したPENGU/FET/Q102/V52基準候補を使用。過去L2、tick順序、非同期freshness、pending注文、実margin余力、注文文字列不具合を完全再現していない。freshness Gateは原因未確定のため緩めない。BTの資産成長率をLIVE期待値として扱わない。

`comparison-summary.json` と `cases/*/runs/*/metrics.json` に全指標、gzip JSONLに候補・採否・約定・Funding・会計台帳を保存。`independent-verification.json` は全48台帳の損益/勝率/PF/イベントcashflow/所有権/入金を独立再計算した結果。MTM DDは独立再計算していない。`artifact-manifest.json` に成果物SHA256。

1. 既存Aster H1/Funding/FXの研究データを準備。旧参照データ位置は `DISDEX_REFERENCE_BT_ROOT`、市場データ位置はsupport wrapperの設定を確認する。
2. `all_gate_ablation.cjs --export-all-exits V12 Q102 HYPE IDLE RESIDUAL` をNodeで実行する（スクリプトは既存TypeScript依存を読み込む）。exportモードはgate-fixes結果フォルダへ出力する。Entry/Exitのsource manifestを照合する。
3. `python scripts/research/run_gate_fix_comparison.py` で16案を再実行。`DISDEX_GATE_BT_COSTS`は既定10,20,30。
4. `tsx scripts/research/verify-idle-quantity-parity.ts`、`python scripts/research/verify_gate_fix_comparison.py` で検証。

根拠となる市場アーカイブは既存研究データを利用し、本フォルダに巨大な市場データ自体は複製しない。support内にはhash検証済み参照engineを保存した。LIVEデプロイは未実施。
