# PRISM VII — PENGU SHORT V20「負け取引を勝ちに変える」再設計プロトコル（2026-11-22）

## 状態・境界

**RESEARCH PROTOCOL ONLY / 80% NOT PROVEN / NO NEW BT / NO PRODUCTION CHANGE.**

基準はPR #594 / PRISM VI head `da5c1e5f63550a4f175f338da6bcd828e3760ff7`、元ネイティブ固定SHA `1657e173d250ad58f53e62f7bb0a3428fb405496`、SHORT V20自然発火53件。30bps価格モデル29勝24敗（54.72%）、平均＋1.0007%、価格PF約1.377。前6・基準40・後7は**すべて閲覧済みの開発検証期間**であり、真の未見OOSではない。実取引所約定／Funding／ポートフォリオDDは未証明。

### 方針修正（Owner意向）
- **候補／取引回数を大量に捨てて勝率を水増しするフィルタは採用しない。** 53原候補それぞれに1つの対応判断を残し、基準取引数・成立取引数・見送り/未約定・失われた既存勝ちを別々に数える。見送りを勝ちに算入しない。
- 方向判定だけでなく「最初から方向を外した負け」「十分下落後に利益を失った負け」「小幅下落後に負けた取引」を別機構として再設計する。PENGU SHORT V20はSHORT専用のまま、逆方向LONGへの単純反転は行わない。
- 53件での80%は最低43勝を要する。元29勝すべてを保持したとしても、少なくとも**14敗を勝ちに転換**する必要がある。どの14件を転換できたか、どの元勝ちを壊したかを個別台帳に記録する。単に14件を除外しても達成とは扱わない。
- ただし、現実の上昇相場などSHORTの優位性が存在しない期間に「必ずエントリーする」ことを安全要件より優先しない。安全な見送りが必要な場合は機会損失と未達をそのまま報告する。

## 再設計する論理（研究仮説、実装・採用未済）

### Stage A — エントリー時点の構造を分解する
既存SHORT候補の確定時刻で、未来値を使わず以下を別々に測る：
1. **売りの持続性**：直近6/12/24Hの安値・戻り高値の更新順序、連続陰線よりも高値切下げの持続、PENGU対BTCの相対弱さ、複数市場の下げbreadth。
2. **売り過熱・吸収**：直前に大きく下落したのに安値更新が鈍る構造、出来高を伴う下ヒゲ、taker買いの継続、反発高値を取り戻す過程、BTCとPENGUの価格先行遅行。
3. **ボラ別の現実的目標距離**：as-of ATR、過去に観測済みの価格変位・効率・時間当たりの順行分布と、費用・STOP幅との比率。将来MFEは入力禁止。
4. **成行／限定的再試行の執行可能性**：M5の正出来高print、約定代理価格と遅延・滑り・板厚の不足を別フラグにする。未確認は不確実のまま残す。

Stage Aで使う補助特徴量は、少数の経済的機構ごとに固定し、53件の勝敗を見ながらの多数閾値探索は禁止。目的は「売り転換」「下落継続」「ショートスクイーズ」の**因果的に観測可能な相場状態**を識別すること。入口の異常検知と経済的にSHORTを持つ価値は別ラベルにする。

### Stage B — 11件の「そもそも下げない」を改善する
元53意図を保持し、同じSHORT候補について即時型と市場構造確認型を**事前固定の分岐**で比較する。ただし「入口を一律N時間遅らせる」「条件非合致なら単に捨てる」は既に反証された。
- 売りの新規確認は確定M5のみ、検知後の**次の実行可能時刻**から再価格する。後から見て一番良いM5安値で約定させない。
- 未成立・安全上の見送りは敗戦候補削除に算入せず、元候補あたり損益を現金0として計上し、成立件数・取り逃がした元勝ち・時間占有を併記する。
- 11件中、真の方向不一致を改善できたケースと、単に取引を消しただけのケースを分離する。

### Stage C — 7件の「大きく下げたのに損失」を改善する
MFE3%以降を事後に検知したことにせず、**確定足で初めて利益閾値を認識した時刻**・次足のSTOP発効時刻・約定方向をnative POSITION/STOP stateで再生。追随STOP・部分利益確定・保有継続の3対照を、native勝ち29件も含む全53件へ適用する。
- 現行のH48短縮、一律+0.5%保護は採用済み解ではない。+2%確定後+0.5%保護の過去試験は33/53勝だが30bps平均-0.028%で、元平均+1.001%を破壊している。
- 既存の大きな勝ちの利益を削る修正を禁止しないが、**全候補期待値・PFの劣化を合格扱いしない**。
- 実取引上のresident STOP、注文競合、単一銘柄ネットポジションでの部分決済の整合性を別契約として検証。

### Stage D — 6件の「小さく下げてから負ける」を改善する
入口時点の現実的下落余地とSTOP・実行コストに対し利益を確保する値幅が小さいケースを分析し、保有中の下降効率・高値の更新・売り出来高消失の時点に基づく時間依存の出口分岐を比較する。native EXITを再計算し、後で分かったMFEを使ったトリガーは禁止。

## 検証プロトコル（この順に固定）

1. **完全再現・品質**：現行Production pinの実装経路と元固定SHAの差を明示。元53/53 native EXIT一致、H1/M5不整合分類、M5 zero-printの執行不可解釈を確認。研究用価格モデルと実約定を混同しない。
2. **反事実全件再生**：53原候補の各1件をIDで突き合わせ、before/after entry price, entry timestamp, size, EXIT, fees, Funding推定、STOP state, PnL, holding time, original-win-retained, original-loss-converted, new-loss-created, unfilled を保存。出口の差がある場合は必ず固定native函数を新入口で再実行。
3. **損失機構ごとのアブレーション**：Stage Bのみ／Cのみ／Dのみ／B+C+Dを同じ原53意図で比較。発火数と実際の成立取引数を分離し、勝率=勝ち/成立取引と「原53機会あたり勝ち」両方を報告。
4. **開発→時間順walk-forward**：過去の3期間は調整用・既見確認用であり未見OOSではない。機構・閾値・合否を凍結後、**別の未閲覧期間・別相場**のみを新OOSに採用。時系列purge/embargo、ブロック単位誤差、期間別・ボラ帯別・サンプル数と信頼区間を記載。
5. **独立人工相場（事前固定シード）**：価格・volume・buy-taker-share・BTC連動を伴う、レンジ→トレンド→反転、急騰squeeze、連続急落、ボラ縮小/拡大、板薄・zero-print、ジャンプ/ギャップ、強いBTC逆風、流動性断絶のレジームスイッチを別々に生成。損失を見てからgeneratorやシードを調整しない。平均的な仮想市場だけでなく悪条件・未観測組合せでの脆弱性を記録。上昇トレンドのみの市場でSHORTの80%と取引数維持を無理に要求せず、ノートレードと機会損失を正直に数える。
6. **総合Production同値BT**：対象2025-10-01 00:00 UTC〜2026-10-01 00:00 UTC終端除外、初期1万円、単利/複利区別のうち判定は複利、10/30bps独立、固定Production pins＋Gross、Shared Risk、Funding、resident STOP、実際の重複候補・占有・決済を再生し、全Runner/ルート別の勝率・期待値・PF・最大DDを確認。基準研究Gross425とProductionを混ぜない。

### 研究合格条件（達成宣言のために必要な証拠）
- PENGU SHORT V20 **80%以上**は目標であって現在未達。自然候補基準の29/53より改善し、他PENGU経路を含めてPENGU全体80%を別判定。全Runner各経路70%以上が目標。
- 取引数削減による見せかけ改善を禁止。53候補に対する未約定・見送り・元勝ち損失をすべて報告。取引維持が不可能な場合は**未達**（ただし安全上の見送りは許容）。
- 10/30bps双方で少なくとも元の期待値とPFを維持／向上。ポートフォリオの最大DDが20%以下。DDは元本比ではなく逐次資産ピーク基準の最大DDとして算出。
- 未使用相場での失速・各レジームの損失・データ品質と約定ストレスを開示。標本53件の80%だけでは証明にならず、信頼区間、十分な件数と独立性、他期間再現を必要とする。
- 本番反映は別PR・CI・Owner承認ルートの後にのみ。**本研究PRからRunner／注文／建玉／STOP／HYPE／VPS／Kill Switchは変更しない。**
